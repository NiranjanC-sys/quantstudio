## The intended solution

The phase-flip code is the bit-flip code conjugated by Hadamards, and so is
everything about it. The circuit follows that sentence literally:

```text
ry(pi/4) 0 ; CNOT 0->1 ; CNOT 0->2      encode into the bit-flip code
h 0 ; h 1 ; h 2                          rotate into the phase-flip code
z 1                                      the error
h 0 ; h 1 ; h 2                          rotate back
CNOT 0->3 ; CNOT 1->3                    parity of data 0 and 1
CNOT 1->4 ; CNOT 2->4                    parity of data 1 and 2
h 0 ; h 1 ; h 2                          rotate back into the code frame
```

Seventeen ops, depth 10, six two-qubit gates, and the ancillas end deterministic
at $11$.

Why $11$: the stabilisers of the phase-flip code are $X_0X_1$ and $X_1X_2$. A
$Z$ on qubit 1 anticommutes with both of them, because $Z$ anticommutes with $X$
on the same wire and qubit 1 appears in both stabilisers. Anticommuting with a
stabiliser is what a syndrome bit of 1 means, so both bits are 1. A $Z$ on qubit
0 would give $10$ and a $Z$ on qubit 2 would give $01$, which is what makes the
syndrome a decoder rather than a mere detector.

## Why the rotation, and why not just use CZ

The tempting shortcut is to skip the Hadamard sandwich and extract the $X$-type
parity directly, using controlled-$Z$ gates from the data onto an ancilla
prepared in $\ket{+}$. That is a real technique and it is what you would do on
hardware with a native CZ. It also spends more gates here: each parity needs the
ancilla prepared in $\ket+$, two CZ gates, and a Hadamard to bring the ancilla
back to the computational basis for reading, which is six ops per stabiliser
against the four the Hadamard sandwich uses when the sandwich is shared between
both stabilisers.

The deeper reason to write it as a conjugation is that it generalises. Every CSS
code has $X$-type and $Z$-type stabilisers, and the $X$-type extraction is always
the $Z$-type extraction conjugated by a transversal Hadamard layer. Learn it once
and the Steane code's six stabilisers cost you three new circuits, not six.

## Why the naive answer is wrong

The naive answer is to plant the $Z$ error in the computational basis, before
the Hadamard layer, rather than in the encoded frame. A $Z$ on qubit 1 applied to
$\alpha\ket{000} + \beta\ket{111}$ is a logical $Z$, not a correctable error: it
commutes with both bit-flip stabilisers, produces syndrome $00$, and quietly
corrupts the logical state. The circuit runs, the ancillas read $00$, and nothing
warns you. That is the failure mode error correction exists to prevent, and
getting the error into the right frame is the point of the exercise.

## Common wrong answers

Extracting $X_0X_1$ and $X_0X_2$ instead of the two adjacent pairs is a
defensible choice of generators, since $X_0X_2 = X_0X_1 \cdot X_1X_2$ and the
pair generates the same stabiliser group. It also changes the syndrome table: a
$Z$ on qubit 1 anticommutes with $X_0X_1$ and commutes with $X_0X_2$, so the
ancillas read $10$ and the check rejects it. The syndrome is a property of the
generators you chose, not of the error alone, which is worth knowing before you
write a decoder against someone else's convention.

Omitting the final Hadamard layer leaves the data in the wrong frame. It does not
change the ancilla marginal, so this problem's check still passes, but the state
you hand to the next round of correction is no longer in the code space.

A quantum circuit with a conditional gate is no longer a picture of a unitary. It
is a program with an `if` in it, and the value the `if` tests did not exist when
the program was written. That is the whole content of classical control, and it
is what turns teleportation from a derivation into something a device can
actually execute.

## The IR

An operation in this platform's circuit IR carries an optional `condition` with
two fields: a list of classical bit indices and an integer value. The operation
executes only when those bits, read as a binary number, equal that value.

```json
{ "id": "fx", "gate": "x", "targets": [2],
  "condition": { "bits": [1], "value": 1 } }
```

That is "apply $X$ to qubit 2 if classical bit 1 is set". For more than one bit,
the list is ordered **least significant first**: `bits: [0, 1]` with `value: 3`
means $c_0 = 1$ and $c_1 = 1$, while `value: 1` means $c_0 = 1$ and $c_1 = 0$.

<Margin label="Read the order twice">
Classical bit ordering inside a condition is least significant first, which is the
opposite of the qubit convention. Qubit 0 is the most significant bit of a basis
string; classical bit 0 is the least significant bit of a condition value. Both
appear in the same operation list, so check which one you are looking at.
</Margin>

into $c_0$ and $c_1$, and an $X$ on qubit 2 that fires only when both are 1.

The surviving strings are $\ket{000}$, $\ket{010}$, $\ket{100}$ and $\ket{111}$.
The missing four are exactly the ones that would violate
$q_2 = q_0 \wedge q_1$.

## Teleportation, executed rather than derived

The correction table you derived in T1.M7.L2 was: apply $X$ to Bob's qubit if
$c_1 = 1$, then $Z$ if $c_0 = 1$. In the IR that is two operations with
conditions, and nothing else.

      { id: "m0", gate: "measure", targets: [0], cbits: [0] },
      { id: "m1", gate: "measure", targets: [1], cbits: [1] },
      { id: "fx", gate: "x", targets: [2], condition: { bits: [1], value: 1 } },

The message is $\ket{1}$, so the correct answer is that qubit 2 ends in $\ket{1}$
whatever Alice measured. Every surviving basis string in the panel has a final
label of 1: the probability that qubit 2 reads 1 is exactly $1$, averaged over all
4096 trajectories. The four measurement outcomes each occur about a quarter of the
time, and the two conditional gates repair all four branches.

Delete the conditional $Z$ and the protocol still works for this particular
message, because $Z\ket{1} = -\ket{1}$ is a global phase. Delete the conditional
$X$ and it breaks immediately, because half the branches deliver $\ket{0}$. That
asymmetry is a property of the message, not of the protocol; teleport $\ket{+}$
instead and the missing $Z$ becomes fatal while the missing $X$ becomes harmless.

<Callout tone="gotcha" title="Conditions are not controls">
A `condition` reads a classical bit that already has a value. A `control` reads a
qubit that may be in superposition, and entangles with it. Writing a control where
you meant a condition gives a circuit that is coherent instead of collapsed, and
the two agree only through the principle of deferred measurement.
</Callout>

## Why the gate time stops mattering

Count the physical work in that teleportation circuit: five gates before the
measurements, two after. On superconducting hardware those seven operations take
well under a microsecond in total.

Now count the waiting. Each measurement integrates a readout signal for roughly a
microsecond. The result is digitised and sent to a controller. The controller
evaluates the condition. The decision is turned into a pulse and sent back. The
whole feed-forward loop is typically longer than every gate in the circuit put
together, and during it qubit 2 does nothing but decohere.

This is why "dynamic circuit" support is quoted as a latency figure rather than a
gate count, and why hardware teams work hard to move the conditional logic close
to the qubits. The rule to carry forward: in a circuit with feed-forward, the
resource you are spending is the number of classical round trips, not the number
of gates. Two round trips in series cost more than fifty gates in parallel.

<Check question="You write `condition: { bits: [0, 1], value: 2 }`. Which classical outcomes fire the gate?">
Only $c_0 = 0$ and $c_1 = 1$. The list is least significant first, so $c_0$ carries
weight $1$ and $c_1$ carries weight $2$, and the value $2 = 0 \cdot 1 + 1 \cdot 2$
picks out that one combination. If you meant "fire when $c_0 = 1$ and $c_1 = 0$"
you wanted `value: 1`. A condition always tests the full listed register for
equality, so there is no way to express "either bit set" in a single condition;
that needs two operations, or a classical register you have already reduced.
</Check>

Everything so far has assumed you know the state. On hardware you do not: you
have a preparation circuit you believe in and a device that may disagree. **State
tomography** is the measurement procedure that turns counts back into a state,
and for one qubit it is three experiments and six numbers.

## What you are reconstructing

A one-qubit state, pure or not, is fixed by its Bloch vector
$\vec{r} = (r_x, r_y, r_z)$ through

$$
\rho = \frac{I + r_x X + r_y Y + r_z Z}{2},
\qquad r_a = \expect{A} = \tr(\rho A) .
$$

Three real numbers, so three expectation values suffice, and each expectation
value is a single-basis experiment. T1.M5.L3 develops $\rho$ properly. For this
lab, take on trust that $\vec{r}$ determines everything measurable about the
qubit, and that recovering $\vec{r}$ is therefore the whole job.

<Margin label="Estimator">
For a $\pm 1$-valued observable, $\expect{A} = \Pr[+1] - \Pr[-1]$. With $n_0$
counts of outcome 0 and $n_1$ of outcome 1 out of $N = n_0 + n_1$ shots, the
estimator is $\hat{r} = (n_0 - n_1)/N$. It is unbiased and lies in
$[-1, 1]$ by construction.
</Margin>

## The three circuits

Each axis is a basis change from T1.M2.L3 followed by the one measurement the
hardware offers.

| axis | gates before measuring | reported 0 means |
| --- | --- | --- |
| $z$ | none | $\ket{0}$ |
| $x$ | $H$ | $\ket{+}$ |
| $y$ | $S^{\dagger}$, then $H$ | $\ket{+i}$ |

Take as the unknown the state prepared by $R_y(\pi/3)$, which is
$0.866025\ket{0} + 0.5\ket{1}$. Its exact Bloch vector is
$(\sin(\pi/3),\, 0,\, \cos(\pi/3)) = (0.866025,\, 0,\, 0.5)$, and the three
circuits should reproduce it.

Reading off: $r_z = 0.75 - 0.25 = 0.5$, $r_x = 0.933013 - 0.066987 = 0.866025$,
$r_y = 0.5 - 0.5 = 0$. That is the exact answer, because these figures report
exact probabilities rather than samples. Hardware will not.

## Your task

Implement

```python
def bloch_vector(
    counts_z: dict[str, int],
    counts_x: dict[str, int],
    counts_y: dict[str, int],
) -> list[float]:
    ...
```

returning $[r_x, r_y, r_z]$. Each argument maps the bitstrings `"0"` and `"1"`
to shot counts from the corresponding setting. Note the argument order is
$z, x, y$ and the return order is $x, y, z$; the hidden tests check both. Handle
a missing key as a count of zero, and a total of zero shots as a component of
zero rather than a division error.

## Purity, and the estimate that exceeds 1

The **purity** of the reconstruction is the squared length
$\lVert \vec{r} \rVert^2 = r_x^2 + r_y^2 + r_z^2$. For the state above,
$0.866025^2 + 0^2 + 0.5^2 = 0.75 + 0.25 = 1$ exactly, which says the state is
pure and sits on the surface of the Bloch sphere. A mixed state gives less than
1, and the maximally mixed state gives 0.

<Callout tone="gotcha" title="Purity above 1 is a statistics artefact, not physics">
No state has purity above 1. Estimates routinely do. Each $\hat{r}_a$ has
standard error $\sqrt{(1 - r_a^2)/N}$, and squaring a noisy estimate of a
component near $\pm 1$ is biased upward: $\expect{\hat{r}^2} = r^2 + \mathrm{Var}(\hat{r})$.
With $N = 1024$ shots per setting and the state above, the standard error on
$\hat{r}_x$ is about $0.0156$, so purity estimates near $1.02$ are ordinary. Report
the number you measured and its error bar. Clipping it to 1 hides the very
inconsistency that would tell you the shot count is too low.
</Callout>

Three failure modes are worth recognising when the number comes back wrong.
A purity far below 1 with all three components small means the device is noisy
or the qubit is entangled with something. A purity near 1 with the wrong
direction means a basis-change gate is in the wrong order, usually $H$ before
$S^{\dagger}$ instead of after. A purity above about $1 + 3/\sqrt{N}$ means
something is wrong with the counts themselves, not with the state.

<Check question="A run gives $z$ counts $\{0: 750,\ 1: 250\}$, $x$ counts $\{0: 500,\ 1: 500\}$ and $y$ counts $\{0: 500,\ 1: 500\}$. What is the Bloch vector and the purity, and what does it tell you?">
$\hat{r}_z = (750 - 250)/1000 = 0.5$, $\hat{r}_x = 0$, $\hat{r}_y = 0$, so
$\vec{r} = (0, 0, 0.5)$ and the purity is $0.25$. The state is mixed, halfway
between $\ket{0}$ and the centre of the ball. It is not
$0.866025\ket{0} + 0.5\ket{1}$, which has the same $z$ component but purity 1:
the two are indistinguishable in the $z$ basis alone, and the $x$ setting is
what separates them.
</Check>

<Solution>
Write one helper that turns a counts dictionary into an expectation value, then
call it three times and permute:

```python
def _expectation(counts):
    n0 = counts.get("0", 0)
    n1 = counts.get("1", 0)
    total = n0 + n1
    return 0.0 if total == 0 else (n0 - n1) / total
```

Then `bloch_vector` returns
`[_expectation(counts_x), _expectation(counts_y), _expectation(counts_z)]`.
The only trap is the reordering, and the only edge case is the empty
dictionary.
</Solution>

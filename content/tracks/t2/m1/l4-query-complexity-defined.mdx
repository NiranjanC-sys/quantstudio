Almost every theorem you will meet in this track is a statement about queries,
not about seconds. That is a deliberate retreat: nobody can prove a lower bound
on the running time of an arbitrary quantum algorithm, but query lower bounds are
provable, and they are the only unconditional separations the subject has. The
retreat costs something, and knowing exactly what it costs is the difference
between reading an advantage claim and believing one.

## Three complexities of the same function

Fix a function $f: \{0,1\}^N \to \{0,1\}$. The input is a string $x$ of $N$ bits,
and an algorithm learns about it only by asking for individual bits $x_i$. Count
the questions.

**$D(f)$**, the deterministic query complexity, is the depth of the shallowest
decision tree that outputs $f(x)$ for every $x$. Each internal node asks for one
bit and branches on the answer.

**$R(f)$**, the bounded-error randomised query complexity, is the same but the
algorithm may flip coins and must be right with probability at least $2/3$ on
every input. The constant $2/3$ is arbitrary: majority voting over $O(\log(1/\delta))$
independent runs pushes the error to $\delta$, so any constant above $1/2$ gives
the same complexity up to a factor.

**$Q(f)$**, the bounded-error quantum query complexity, is the smallest $T$ such
that some circuit of the form

$$
U_T \, O_x \, U_{T-1} \, O_x \cdots U_1 \, O_x \, U_0 \ket{0}
$$

outputs $f(x)$ with probability at least $2/3$, where $O_x$ is the oracle for the
input string and the $U_j$ are arbitrary unitaries independent of $x$. The $U_j$
may be as complicated as you like and cost nothing. Only the $O_x$ calls count.

<Margin label="What the model gives away">
Letting the $U_j$ be free is what makes lower bounds provable and what makes the
model an incomplete account of reality. A $Q(f)$ of 1 tells you the information is
extractable in one query; it tells you nothing about whether the extracting
unitary can be built from a polynomial number of gates. Every algorithm in this
track has to be checked twice: once for queries, once for gates.
</Margin>

The definitions nest, since a quantum algorithm can simulate a randomised one and
a randomised one can simulate a deterministic one:

$$
Q(f) \le R(f) \le D(f) \le N .
$$

## OR, computed three ways

Take $f = \mathrm{OR}_N$, which is 1 unless every input bit is 0.

$D(\mathrm{OR}_N) = N$. An adversary answers 0 to the first $N-1$ queries. The
algorithm has seen nothing but zeros, so both remaining completions of the input,
all-zeros and one-one-at-the-unqueried-position, are consistent with what it
knows, and they have different answers. It must ask the last bit.

$R(\mathrm{OR}_N) = \Theta(N)$. Randomisation does not help, because on an input
with exactly one 1 placed uniformly at random, $T$ queries find it with
probability at most $T/N$, and an algorithm that has not found it cannot beat a
coin flip. Getting to error $1/3$ needs $T = \Omega(N)$.

$Q(\mathrm{OR}_N) = \Theta(\sqrt{N})$. The upper bound is Grover, which is the
whole of Module 2. The lower bound is BBBV, which is T2.M2.L9. Both halves are
tight, and this is the canonical quadratic separation.

| $N$ | $D$ | $R$ | $Q$ |
| --- | --- | --- | --- |
| $16$ | $16$ | $\Theta(16)$ | $4$ |
| $1024$ | $1024$ | $\Theta(1024)$ | $32$ |
| $10^{6}$ | $10^{6}$ | $\Theta(10^{6})$ | $1000$ |

For a smaller and completely explicit example, take $\mathrm{SEARCH}_4$: four
indices, promised that exactly one is marked, report which. Deterministically you
may need three queries, because two queries can come back unmarked and leave two
candidates. One quantum query settles it exactly.

## How large can the gap get

For **total** functions, defined on every input string, not very. Beals, Buhrman,
Cleve, Mosca and de Wolf proved $D(f) = O(Q(f)^6)$ using the polynomial method of
T2.M9.L1, and the exponent has since come down to 4, which is tight. So no total
Boolean function admits more than a polynomial quantum speedup in queries, and
the quadratic gap of OR is close to the best there is.

Every exponential separation you have seen is therefore a **partial** function,
one defined only on inputs satisfying a promise. Deutsch-Jozsa is 1 query against
$2^{n-1}+1$ deterministic, but only under the constant-or-balanced promise. Simon
is $O(n)$ against $\Omega(2^{n/2})$ randomised, but only when $f$ really does hide
an XOR mask. Take the promise away and both collapse.

<Callout tone="warning" title="A query speedup is not a speedup">
Grover finds a marked item among $N$ in $O(\sqrt N)$ queries. If the "database"
is $N$ classical records in memory, building the oracle means reading all $N$ of
them, and the total time is $\Omega(N)$: no speedup at all, and the quantum
version is slower. The speedup is real only when the oracle is *computed* rather
than *looked up*, as it is when $f$ is a SAT formula or a hash preimage check.
Every honest quantum advantage claim states the cost of one oracle call.
</Callout>

The same caution cuts the other way. Order finding in T2.M5 makes a polynomial
number of queries to a modular-exponentiation unitary that itself costs
$O(n^3)$ gates, so the query count understates the work by a large polynomial
factor, and the algorithm is still exponentially faster than the best known
classical factoring. Query complexity is a lower bound on effort and a bound on
what interference can buy. It is not a runtime.

<Check question="Someone reports a function with $Q(f) = 1$ and $D(f) = N$. Should you expect $f$ to be total?">
No. If $f$ were total, the relation $D(f) = O(Q(f)^4)$ would force $D(f) = O(1)$,
contradicting $D(f) = N$ for large $N$. So $f$ must be partial, and the interesting
question becomes what the promise is and whether real inputs satisfy it.
Deutsch-Jozsa is exactly this shape: $Q = 1$, $D = 2^{n-1}+1$, and a promise that
no naturally occurring function obeys.
</Check>

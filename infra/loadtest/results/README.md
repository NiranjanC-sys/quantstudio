# results/

Output directory for load-test runs. Nothing in here is checked in except
this file, `REPORT-TEMPLATE.md`, and `.gitkeep` - everything else is
generated by a run and is gitignored.

What lands here, per script:

| File | Written by | Contents |
|---|---|---|
| `contest-submission-log.json` | `contest-burst.js` `handleSummary()` | The full deterministic submission plan (every planned submission: user, problem, attempt number, planned verdict, idempotency key) - regenerated from `CONTEST_SEED`, not collected from VUs (see the isolated-memory comment in `contest-burst.js`) |
| `contest-standings-report.json` | `contest-burst.js` `handleSummary()` | Locally-replayed expected standings vs. the server's actual final standings, plus the monotonicity-violation and standings-diff counts |
| `soak-report.json` | `soak.js` `handleSummary()` | Per-service, per-metric first-quartile vs. last-quartile means and the 10%-growth pass/fail verdict (`memoryGrowthOverallPass`) |

To write a human-readable run report, copy `REPORT-TEMPLATE.md` to
`results/<date>-<target>-<git-sha>.md` and fill it in using the JSON files
above plus k6's own end-of-run summary output.
